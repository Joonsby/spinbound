## 2. 시각적 완성도를 제한하는 요소

1. **해상도**: 모든 텍스처가 1배 해상도이고 렌더 해상도도 1배라 고DPI 기기에서 흐릿합니다
2. **도형 품질**: `Graphics`는 그라데이션을 텍스처로 굽지 못하고 외곽선 처리가 없어 평면적인 "도형 모음"처럼 보입니다
3. **캐릭터 구조**: 포즈마다 통째로 그린 프레임이라 포즈 사이 연결 동작(변형·착지·스프링·줄)이 없고, 참조 이미지의 로봇(귀 지느러미·큰 헬멧·바퀴 다리)과 디자인이 다릅니다
4. **깊이감**: 배경이 실루엣 2층뿐이라 원근감·대기 원근(먼 곳일수록 흐리고 푸른색)이 없습니다
5. **지형**: 위·옆·모서리 구분이 없는 사각 타일이라 "판"처럼 보입니다
6. **오브젝트 가독성**: 체크포인트·골·안내판이 개발용 도형/텍스트 박스입니다
7. **이펙트**: 단색 스파크 위주라 행동별(먼지·스파크·착지·타격) 구분이 약합니다
8. **카메라**: 고속 이동 시 시야 확대가 없습니다
9. **UI**: 웹 앱처럼 보이는 단색 패널·버튼

## 3. 재사용할 수 있는 기존 그래픽·로직

- `Player.pose()`와 물리 상태(rolling·held·hurt·dead·boost) — 새 리그의 입력으로 그대로 사용
- 충돌체와 그림의 분리(`VisualSync`, 플레이어 30×42 충돌체) — 그림만 교체하면 판정 불변
- 이펙트 풀 구조(`GameEffects`), 히트스톱, 카메라 셰이크
- 카메라 전방 시야 계산(`SpeedCamera`)
- 보스 상태 머신과 약점 코어 표시 구조
- 성능 진단 패널과 디버그 시계(스크린샷·회귀 검증용)

## 5. 아트 파이프라인 개선 계획

- **에셋 매니페스트**: 모든 텍스처 키·논리 크기·피벗을 코드(`src/graphics/asset-manifest.ts`)에서 한곳에 정의
- **외부 PNG 우선, 없으면 폴백**: `public/assets/asset-manifest.json`에 실제 PNG가 등록된 키만 로드하고, 나머지는 코드로 그린 임시 그림을 같은 키로 생성
- **@2x 규격**: 텍스처 1px = 화면 0.5 논리 px. 품질 설정에 따라 렌더 배율(1·1.5·2) 적용
- **파츠 기반 애니메이션**: 파츠 모양은 고정, 위치·회전·스케일·표정 텍스처만 바뀌어 프레임 간 구조 변형이 없음
- **품질 프리셋**: LOW·MEDIUM·HIGH로 렌더 배율·입자 수·잔상·배경 레이어·장식 조절. 충돌·물리는 품질과 무관

## 6. 성능 위험 요소

| 위험 | 대응 |
|---|---|
| 렌더 배율 2배 = 픽셀 4배(필레이트) | 기기 등급 추정 기본값 + 품질 설정 + 실행 중 FPS 감시 후 단계 하향 |
| 대형 배경 텍스처 메모리 | 현재 테마만 굽고 다른 테마 텍스처 해제, 레이어를 띠(band) 높이로 잘라 오버드로 축소 |
| 시작 시 텍스처 굽기 시간 | 테마 단위 캐시(같은 테마 재시작 시 재사용) |
| 파티클·잔상 | 품질별 상한, 풀 재사용 |
| 텍스트 해상도 | 렌더 배율에 맞춘 `resolution` 지정 |
